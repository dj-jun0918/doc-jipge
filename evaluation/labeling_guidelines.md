# Ground Truth 라벨링 가이드라인

**작성**: 임태규 (초안) / 방정우 (보강)  
**버전**: v0.3 (PR#5 Finalized)  
**목적**: 30개 GT 라벨링 기준 통일 — ann_001~030 전체 일관성 확보 및 가이드라인 최종 확정

---

## 1. 파일 구조

```
evaluation/ground_truth/ann_NNN/
└── ground_truth.json
```

### ground_truth.json 필드 명세

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `announcement_id` | string | ✅ | `"ann_001"` 형식 |
| `title` | string | ✅ | 공고 원문 제목 그대로 |
| `source_url` | string | ✅ | 공고 원문 URL |
| `fields` | array | ✅ | 자격요건 필드 목록 (표준 7종만) |
| `exclusions` | array | ✅ | 신청제외 조건 목록 (없으면 `[]`) |
| `notes` | string | ❌ | 라벨러 판단 메모, 모호한 조건 설명, 매핑 불가 조건 기록 |

---

## 2. 표준 7종 필드 정책

`fields` 배열에는 **아래 7가지 `field_name`만** 사용한다.

| # | field_name | 설명 |
|---|-----------|------|
| 1 | `"업력"` | 창업 후 경과 연수 조건 |
| 2 | `"매출"` | 매출액(또는 매출) 조건 |
| 3 | `"지역"` | 소재지 조건 |
| 4 | `"나이"` | 대표자/신청자 연령 조건 |
| 5 | `"종업원 수"` | 임직원 수 조건 |
| 6 | `"업종"` | 허용/제외 업종 조건 |
| 7 | `"인증"` | 보유 인증 조건 |

### 비표준 자격요건 처리 원칙

| 케이스 | 처리 방법 |
|--------|-----------|
| 표준 7종과 의미가 같은 자격요건 | 표준 필드명으로 매핑. 예: `"스타트업 업력"` → `"업력"` |
| 표준 7종으로 매핑하기 어려운 자격요건 | `fields` 제외, `notes`에 원문과 매핑 불가 사유 기록. 예: `"대표자 국적"` |
| 메타 정보 (사업기간/신청방법/지원한도/제출서류 등) | **자격요건이 아니므로 `fields`에서 완전 제외** |

> ⚠️ `fields`는 오직 **"이 공고에 신청하려면 어떤 자격을 갖춰야 하는가"** 에 대한 답만 담는다.  
> 지원 내용, 사업 일정, 제출 서류, 지원 금액 등은 메타 정보이므로 절대 포함하지 않는다.

## 3. 필드별 라벨링 기준

### 3-1. 업력

- `field_name`: `"업력"`
- `condition`: 공고 원문 의미를 유지하되, 사용자 화면에서 바로 이해 가능한 형태로 기재
  - 예: `"3년 미만"`, `"7년 이하"`, `"6개월 이상"`, `"1년 이상 7년 이하"`, `"창업 후 7년 이내"`
- `evidence`: 조건이 명시된 원문 문장 그대로 인용
- `evidence_source`: 페이지 및 항목 위치 명시

**operator 매핑 기준**

| 원문 표현 | operator |
|-----------|----------|
| N년 미만 | `"미만"` |
| N년 이하 | `"이하"` |
| N년 이상 | `"이상"` |
| N년 초과 | `"초과"` |
| N년 이상 M년 이하/미만 | `"범위"` |

> ⚠️ `"미만"`과 `"이하"` 엄격 구분. `"창업 후 3년"` 표현은 문맥상 `"이하"` 또는 `"미만"` 판단하여 `notes`에 근거 기재.  
> ⚠️ 사용자에게 보여지는 값이므로 `"창업 후 7년 이내인 기업"`처럼 긴 문장보다 `"창업 후 7년 이내"`처럼 조건 중심 표현 권장.

---

### 3-2. 지역

- `field_name`: `"지역"`
- `condition`: 정규화된 지역명 사용 (`REGION_GROUPS` 기준)
  - 예: `"서울"`, `"경기"`, `"강원"`, `"전국"`
  - 시·군·구 단위 조건은 원문 그대로 기재 (예: `"광명시"`, `"춘천시"`)
- `operator`: `"소재"` (일반적), `"무관"` (전국 조건)

**전국 조건 처리**
- `"전국 소재"`, `"제한 없음"`, `"지역 무관"` → `condition: "전국"`, `operator: "무관"`

**사용자 표시 관점 보완**
- 지역은 단순 지역명만 쓰면 의미가 모호할 수 있으므로, 사용자 화면 기준으로는 `"강원 소재"`, `"서울 소재"`처럼 해석될 수 있도록 검수
- 단, JSON 값 자체는 기존 기준대로 정규화 지역명을 유지하고, 필요 시 화면에서 `"소재"`를 함께 표시하는 방식 고려
- 시·군·구는 원문 그대로 유지하되, 사용자가 거주지 기준인지 사업장 기준인지 오해할 수 있는 경우 `notes`에 근거 기재

---

### 3-3. 매출

- `field_name`: `"매출"` (일부 공고는 `"매출액"` — 원문 표현 따름)
- `condition`: 원문 의미를 유지하되, 사용자 입장에서 기준이 분명하도록 기재
  - 예: `"2억원 이상"`, `"10억원 미만"`, `"1억원 이상 50억원 미만"`
  - 기준 연도가 명시된 경우 그대로 포함  
    예: `"직전년도(2025) 또는 최근 3개년 연매출 2억원 이상"`

**사용자 표시 관점 보완**
- `"2억원 이하"`처럼 금액만 있으면 사용자가 기준 시점을 오해할 수 있으므로, 원문에 기준 연도나 기간이 있으면 반드시 포함
- 화면에 표시될 값이라는 점을 고려해 `"직전년도 매출 2억원 이하"`처럼 읽히는 형태 권장

---

### 3-4. 종업원 수

- `field_name`: `"종업원 수"`
- `condition`: 원문 그대로 기재
  - 예: `"5인 미만"`, `"10인 이상 300인 미만"`
  - 업종별로 기준이 다른 경우: 업종 구분 포함하여 기재  
    예: `"광업·제조·건설·운수업 10인 미만 / 그 외 업종 5인 미만"`

**사용자 표시 관점 보완**
- 종업원 수 조건은 숫자와 단위가 한눈에 보이도록 유지
- 복합 조건은 화면에서 읽기 쉽도록 `/` 구분 유지

---

### 3-5. 나이

- `field_name`: `"나이"`
- `condition`: 원문 그대로 기재
  - 예: `"만 39세 이하"`, `"만 60세 이상"`
- `"만 나이"` 표현 필수 확인 — `"만"` 없는 경우 `notes`에 명기

**사용자 표시 관점 보완**
- `"39세 이하"`만 적을 경우 사용자가 만 나이 여부를 혼동할 수 있으므로 `"만"` 여부 반드시 확인
- 대표자 기준인지 신청자 기준인지 불명확하면 `notes`에 근거 기재

---

### 3-6. 업종

- `field_name`: `"업종"`
- `condition`: 허용/제외 업종 원문 기재
  - 예: `"제조업"`, `"소상공인 정책자금 지원제외 업종 외"`
- `operator`: `"포함"` (허용 업종 나열), `"제외"` (금지 업종 나열)
- 업종 목록이 긴 경우: 대표 업종 + `"등"`으로 요약 가능, `notes`에 전체 목록 출처 기재

**사용자 표시 관점 보완**
- 업종은 공고 원문이 법률 문장처럼 길어질 수 있으므로, 사용자 입장에서 읽히는 수준으로 정리 가능
- 단, 의미를 바꾸지 않는 범위에서만 요약

---

### 3-7. 인증 (cert_mapping 15종 연동)

- `field_name`: `"인증"`
- `condition`: 요구 인증명 원문 기재
  - 예: `"벤처기업 인증 보유"`, `"이노비즈 인증 보유"`
- `operator`: `"보유"` (인증 있어야 함), `"미보유"` (인증 없어야 함)

**사용자 표시 관점 보완**
- `"벤처기업"`처럼 인증명만 적지 말고, `"벤처기업 인증 보유"`처럼 조건 의미가 드러나게 작성
- 여러 인증 중 택일이면 `condition`에 그대로 반영  
  예: `"벤처기업 / 이노비즈 중 1개 이상 보유"`

#### 인증 표준 키 및 한글 키워드 매핑 (cert_mapping 15종)

함준규 `cert_mapping.py`와 1:1로 정확하게 일치해야 하며, 한글 키워드 표기를 통일한다.

| 표준 키 (Standard Key) | 한글 표준 키워드 목록 (Keywords) | 설명 / 통일 가이드라인 |
|----------------------|-----------------------------------|----------------------|
| `venture_company` | `"벤처기업"`, `"벤처기업 인증"`, `"벤처기업 확인서"` | 벤처기업 특별법에 따른 확인서 포함 |

| `main_biz` | `"메인비즈"`, `"경영혁신형 중소기업"` | 영문 Main-Biz 및 공식 한글 명칭 통일 |
| `iso_9001` | `"ISO 9001"`, `"ISO9001"`, `"품질경영시스템"` | 띄어쓰기 유무 모두 허용하여 매핑 |

| `iso_27001` | `"ISO 27001"`, `"ISO27001"`, `"정보보안경영시스템"` | 띄어쓰기 유무 모두 허용하여 매핑 |
| `iso_22000` | `"ISO 22000"`, `"ISO22000"`, `"식품안전경영시스템"` | 띄어쓰기 유무 모두 허용하여 매핑 |
| `gmp` | `"GMP"`, `"우수의약품제조관리기준"` | 의약품/화장품 제조 기준 한글 명칭 포함 |
| `haccp` | `"HACCP"`, `"식품안전관리인증"` | 해썹(식품안전) 인증 공식 명칭 매핑 |
| `ce_marking` | `"CE"`, `"CE 마킹"` | 유럽 공동체 인증 명칭 및 마킹 표기 일치 |

| `rd_lab` | `"기업부설연구소"`, `"기업부설 연구소"` | 기초연구진흥법 기준 연구소 보유 조건 |
| `ip_protection` | `"특허"`, `"지식재산권"`, `"실용신안"` | 등록 완료된 특허 및 지식재산권 일체 매핑 |

## 4. 모호 케이스 합의 (Kappa < 0.6 의사결정)

임태규/방정우 교차 라벨링(Cross-Labeling) 결과 일치도가 낮았던(κ < 0.6) 조건들에 대한 표준화 합의 사항이다.

### 4-1. "창업 N년 이내" / "창업 후 N년"의 경계값 포함 여부
- **문제**: "창업 후 7년 이내"가 "이하"인지 "미만"인지 모호함.
- **합의**: 원문에 구체적인 예외 일자(예: 2019-04-29 ~ 2026-04-28 설립 등) 또는 명확한 단어가 기재되어 있지 않은 한 **"이하" (경계값 포함)**로 해석하며, `operator`를 `"이하"`로 매핑한다. 단, 기준시점이 애매할 경우 `notes`에 근거를 상세히 기록한다.

### 4-2. 복합/다중 우대 자격요건의 매핑 생략 및 notes 기록
- **문제**: "초격차 스타트업 1000+ 프로젝트 선정 기업" 또는 "TIPS 선정 기업" 등 표준 7종에 정확히 1:1 매핑되지 않는 다중 우대/자격 조건 처리.
- **합의**: 표준 7종에 명확히 들어맞지 않는 복합 요건은 **`fields` 목록에서 제외**하고, 대신 **`notes`에 해당 원문 문구와 자격요건 세부 내용을 명시**한다. (단, 단순 "벤처기업 또는 이노비즈인증 중 1개 보유" 같은 택일형 인증 조건은 `field_name: "인증"` 하위 `condition`에 `"벤처기업 / 이노비즈 중 1개 이상 보유"` 형태로 취합하여 입력 가능)

### 4-3. "중소기업기본법상 중소기업" 자격요건 제외
- **문제**: "중소기업기본법 제2조에 따른 중소기업"이라는 조건이 자격요건인지 기본 대상 구분인지의 여부.
- **합의**: 이는 특정 사업군 전반의 공통 대상 전제(복합 규모 개념)이므로 개별 구체적 수치가 언급되지 않은 단순 선언 조건은 **`fields`에서 제외**하며, 대신 **`notes`에만 기본 참여 대상 정보로 기록**한다.

### 4-4. "업종 제외(exclusions)"와 "업종 자격(fields.업종)"의 분리
- **문제**: 특정 금지 업종이 `fields`의 `"업종"` 조건인지, `exclusions` 항목인지 모호함.
- **합의**: 
  - 신청 자격으로서 특정 업종을 필수로 지정한 경우 (`"포함"`): `fields` 내 `"업종"` (`operator`: `"포함"`)으로 작성.
  - "소상공인 정책자금 지원제외 업종이 아닐 것", "일반 유흥주점업 제외" 등 부정적 필터인 경우 (`"제외"`): `fields`가 아닌 **`exclusions` 배열**에 한 줄씩 분리 기재한다.

### 4-5. 사후 확약 조건 및 미래 의무 사항의 분리
- **문제**: "협약 체결 후 2개월 이내에 관내로 본사 이전 필수" 같은 사후 확약 조건 처리.
- **합의**: 현재 시점의 신청 자격 요건이 아니라 미래 의무 사항(메타/계약 조건)이므로 **`fields`에서 배제**하며, 주요 변동 가능 사항이므로 **`notes`에만 별도 기록**한다.

## 5. condition 작성 규칙

사용자에게 표시되는 값을 기준으로 작성한다.  
즉, `condition`은 공고 원문을 그대로 복붙하는 문장이 아니라, **사용자가 화면에서 보고 바로 이해할 수 있는 형태**로 정리되어야 한다.

### 원문 그대로 vs 정규화

| 케이스 | 규칙 | 예시 |
|--------|------|------|
| 수치 조건 | 원문 의미를 유지하되 간결하게 작성 | `"3년 미만"`, `"2억원 이상"` |
| 지역명 | `REGION_GROUPS` 기준으로 정규화하되, 사용자 입장에서 의미가 분명하도록 작성 | `"서울특별시"` → `"서울"`, 필요시 `"서울 소재"` |
| 시·군·구 | 원문 그대로 사용 | `"광명시"`, `"춘천시"` |
| 복합 조건 | 원문 의미 유지, `/`로 구분 | `"10인 미만 / 5인 미만"` |
| 인증명 | 원문 그대로 쓰되 보유 여부가 드러나게 작성 | `"벤처기업 인증 보유"` |

### 사용자 표시 관점 보완 원칙

- `condition`만 보더라도 사용자가 조건 의미를 이해할 수 있어야 한다.
- 같은 유형의 조건은 공고마다 가능한 한 비슷한 방식으로 표현한다.
- 불필요하게 긴 설명문은 지양하고, 조건 중심 표현으로 정리한다.
- 단, 너무 축약해서 원문 의미가 달라지면 안 된다.

예:
- 나쁨: `"창업 후 7년 이내인 기업만 신청 가능"`
- 좋음: `"창업 후 7년 이내"`

- 나쁨: `"강원특별자치도에 본사 또는 사업장을 둔 기업"`
- 좋음: `"강원 소재"`

## 6. operator 후보 목록

| operator | 적용 필드 | 설명 |
|----------|-----------|------|
| `"미만"` | 업력, 매출, 종업원 수, 나이 | 미만 (경계값 미포함) |
| `"이하"` | 업력, 매출, 종업원 수, 나이 | 이하 (경계값 포함) |
| `"이상"` | 업력, 매출, 종업원 수, 나이 | 이상 (경계값 포함) |
| `"초과"` | 업력, 매출, 종업원 수, 나이 | 초과 (경계값 미포함) |
| `"범위"` | 업력, 매출, 종업원 수, 나이 | N 이상 M 이하/미만 |
| `"소재"` | 지역 | 특정 지역 소재 |
| `"무관"` | 지역 | 전국, 지역 제한 없음 |
| `"포함"` | 업종 | 허용 업종 목록 |
| `"제외"` | 업종 | 금지 업종 목록 |
| `"보유"` | 인증 | 인증 보유 필수 |
| `"미보유"` | 인증 | 인증 없어야 함 |

> ⚠️ `operator`는 내부 비교용이지만, 실제 사용자 화면 표현과 논리적으로 일치해야 한다.  
> 예: `condition = "7년 이하"`인데 `operator = "미만"`이면 사용자에게 잘못된 정보로 보일 수 있으므로 검수 시 반드시 확인

## 7. 단위 변환표

원문 텍스트 내 중구난방인 수치 및 물리 단위를 정규화하여 가독성을 극대화한다.

| 항목 | 원문 표현 예시 | 가이드라인 권장 정규화 형태 | 예시 |
|------|---------------|--------------------------|------|
| **매출** | `2억`, `2,000만 원`, `200,000,000` | `"억원"`, `"만원"` 단위로 통일. 쉼표(,) 제거. | `"2억원 이상"`, `"5,000만원 이하"` |
| **업력** | `3년`, `36개월`, `창업 1년 미만` | `"년"`, `"개월"` 표기 통일. 1년 이상은 가급적 년 단위 사용. | `"3년 이하"`, `"6개월 이상"`, `"1년 이상 7년 이하"` |
| **나이** | `만 39세`, `39세 이하`, `청년(만19세~34세)` | 반드시 **`"만"`** 접두어를 명시하여 정규화. | `"만 39세 이하"`, `"만 19세 이상 만 34세 이하"` |

## 9. confidence / notes 사용 기준

현재 `ground_truth.json` 스키마에 `confidence` 필드는 없으나,  
**사용자 화면에 표시했을 때 의미가 모호해질 수 있는 조건**은 반드시 `notes`에 근거를 남긴다.

### notes에 기재해야 할 케이스

- 조건이 본문이 아닌 첨부파일·별표에만 있는 경우
- `"창업 후 N년"` 표현이 `"미만"`인지 `"이하"`인지 불명확한 경우
- 업종 조건이 포함/제외 목록이 혼재된 경우
- 수치 조건의 기준일(공고일/접수일/신청일)이 불명확한 경우
- 복수 조건이 AND인지 OR인지 불명확한 경우
- 지역 조건이 단순 지역명인지, 소재지 기준인지 사용자가 오해할 수 있는 경우
- 연령 조건에서 `"만 나이"` 여부가 불명확한 경우
- **표준 7종 외 자격요건을 표준 필드로 매핑한 경우** (매핑 근거 기록)
- **표준 7종으로 매핑 불가한 자격요건이 있는 경우** (원문 조건 + 매핑 불가 사유 기록)

## 10. exclusions 작성 규칙

- 원문 의미를 유지하되, **사용자가 읽었을 때 바로 제외 사유를 이해할 수 있도록** 작성한다.
- 한 문장에 여러 조건을 과하게 묶지 말고, 가능한 한 항목별로 분리한다.
- 일반적인 공통 제외 조건 (체납, 휴폐업, 채무불이행)은 반드시 포함
- 업종 제외 조건이 있으면 별도 항목으로 분리

### 작성 원칙

- 원문 그대로 기재를 기본으로 하되, 화면 가독성을 해치지 않는 범위에서 정리 가능
- `[cite: N]` 출처 표기는 선택사항 (ann_001 스타일)
- 사용자가 "나는 제외 대상인지"를 빠르게 판단할 수 있어야 함

## 11. 라벨링 체크리스트 (개인 검수)

- [ ] `title`이 공고 원문 제목과 일치하는가
- [ ] `source_url`이 실제 접근 가능한 URL인가
- [ ] `fields`에 표준 7종 외 필드명이 사용되지 않았는가
- [ ] 표준 7종으로 매핑한 비표준 자격요건은 `notes`에 근거가 기재되었는가
- [ ] 메타 정보(사업기간/신청방법/지원한도/제출서류 등)가 `fields`에서 완전히 제외되었는가
- [ ] 모든 수치 조건에 `operator`가 명확히 매핑되는가
- [ ] `"미만"` / `"이하"`, `"이상"` / `"초과"` 혼동 없는가
- [ ] 지역명이 `REGION_GROUPS` 기준으로 정규화되었는가
- [ ] `condition`만 봐도 사용자가 의미를 이해할 수 있는가
- [ ] 같은 유형의 조건이 다른 공고에서도 비슷한 방식으로 표현되었는가
- [ ] `exclusions`에 휴폐업/체납/채무불이행 포함되었는가
- [ ] `exclusions`가 한 문장씩 읽기 쉽게 정리되었는가
- [ ] 모호한 조건 또는 매핑 불가 조건은 `notes`에 근거가 기재되었는가
- [ ] JSON 문법 오류 없는가 (`python -m json.tool`로 검증)
